# ComfyUI / Dirty-Moss 测试版说明

这是用户 fork 中的小范围实验，不替换原有 NovelAI、OpenAI、Gemini、Grok、文本模型、自动处理、转移或历史功能。旧功能见[主说明](<README.md>)；开发现场与下一步仅在[唯一续接入口](<NEXT.md>)维护。

**交付顺序保持：向用户 fork 提 PR → 用户审核并合并到 main → 用户在 TauriTavern 通过 Git URL 安装。** PR #1 已合并安装，2026-11-17 用户确认插件与 ComfyUI 均可正常生图；当前冻结版本、运行条件与证据边界见 [BASELINE-2026-11-17.md](<BASELINE-2026-11-17.md>)。不要把开发目录或 ZIP 手工复制到在线扩展目录当作正常安装流程；新功能仍须先审核合并。

## 通过 Git URL 安装

1. 先在[用户 fork 的 PR 列表](https://github.com/VegarGG/witch-paintbox-comfy-UI/pulls)审核测试版，由用户决定是否合并到 `main`。不向上游仓库发 PR，不由代理自动合并。
2. 安装前备份现有配置、测试聊天和图片数据；图片历史不是配置导出的一部分，不能只备份配置 JSON。若已经安装其他来源的画匣，先记录原 Git URL/分支并避免同时启用两份。
3. **合并之后**，在 TauriTavern“扩展 → 安装扩展”中填写：

   ```text
   Git URL: https://github.com/VegarGG/witch-paintbox-comfy-UI
   分支或标签名称: main
   ```

   分支也可留空使用仓库默认分支（当前为 `main`）。按自己的使用范围选择“仅为我安装”或“为所有用户安装”。本轮不要求绕过审核直接装测试分支。
4. 等宿主完成 Git 安装后刷新实际页面；应能看到“正文直出 / ComfyUI”菜单和 ComfyUI 设置。若已装这个 fork，则在确认主分支已合并后使用宿主提供的更新流程；不要重复安装两份。
5. [清单](<manifest.json>)指向的构建产物随 PR 一并提交，普通使用者不需要 Node、TypeScript、重新编译或安装 Comfy 自定义节点。ZIP 仅作归档，不是本轮 Tauri 安装入口。

代理不会因此获准安装在线扩展、修改宿主配置、实际生成图片、写聊天或合并 PR；这些操作由用户执行或另行明确授权。

## 两条路径，不要混淆

- **正文直出 / ComfyUI**：选择原生 AI 楼层，默认从正文手选一个剧情瞬间并编辑画面。可独立确认一次酒馆主 API 选帧，或读取[可选的主回复附段](<TAURITAVERN-KEYFRAME-PRESET.md>)；都只填草稿。显式预览正负词后每次提交一张（可选第二帧，分别确认）。不改聊天、不插图片标记、不切换提供方；图片仍进原图库/历史。需要旧方式时选「整段原样直出」。
- **原 AI生图 / 指定插图**：保留原先的预设 AI 处理/标记路径，可能调用已配置的文本模型并写回标记。不要把旧入口当作本实验的无写回入口。迁移不会擅自关闭旧自动开关，第一次验收请自行关闭自动处理/自动批量生图。

基础链为“现有正文 → CLIPTextEncode → 单阶段 MOSS 采样 → VAE 解码 → 一张图片”。必要的文本编码仍保留，没有 TextGenerate 提示词扩写。早期官方模板1024×1024、约181.13秒只是历史背景；本轮基础单阶段与插件收图已由用户实际验证。当前成功profile、中性长文本对照和未测项见[冻结记录](<BASELINE-2026-11-17.md>)，不把单机成功说成完整认证。

| 正文直出配方 | 扩散模型 | 文本编码器 |
| --- | --- | --- |

## 合并安装后的最小验收

### 1. 设置与 GET 检查（不出图）

1. 先关闭自动处理/自动批量功能。在生图服务“更多画笔”中选择 ComfyUI，URL默认 `http://127.0.0.1:8188`，不要填云端密钥。只接受无凭据、query、fragment的回环 HTTP(S) 地址。
2. 核对三个模型及参数，点击“检查连接 / 更新模型枚举（仅 GET）”，然后“应用并保存 ComfyUI 配置”。枚举不会自动替换模型文件名；GET成功不是实际加载或出图通过。
3. 设置页切换服务会改变常规绘图的当前提供方。若需要保留原提供方，保存 Comfy 后可切回；“正文直出 / ComfyUI”始终明确使用保存的 Comfy 配置。
4. 若出现 CORS、混合内容或 WebView 限制，先记录实际 origin 与错误，再决定是否精确允许该 origin。不关闭浏览器安全，不发送云端 Cookie/密钥，不默认开放 `*`。

### 本机 macOS/MPS 的已验证配置

本轮成功所用的两项启动参数如下，参数间用空格，不附加逗号；其他原参数应保留：

```text
--enable-cors-header tauri://localhost --use-split-cross-attention
```

在 Comfy Desktop 当前实例的“实例设置 → 启动参数”保存后，队列空闲时重启该实例，不是只刷新画布。实际日志应为 `Using split optimization for attention`；CORS 响应头应精确匹配 `tauri://localhost`。这是当前模型组合的单机规避方案，不是所有设备的通用性能推荐；不要为此同时改 dtype/CFG/采样器或下载其他 encoder。临时诊断探针不是插件依赖，当前启用与撤回边界见[冻结记录](<BASELINE-2026-11-17.md>)。

### 2. 显式单张（先只做一次）

1. 打开含普通原生 AI 回复的测试聊天副本，不操作原聊天。从悬浮菜单选择“正文直出 / ComfyUI”，选择来源楼层，不限最新一楼。
2. 选「二次元」或「写实」，从完整正文划选一个片段，点「使用选中片段」，只保留一个看得见的动作/表情。也可直接写画面。需要建议时单独确认调用酒馆主 API（可能联网/计费，只发本楼清洗正文，最长 24,000 UTF-16 码元、不截断）；可选预设附段读取不另发请求。思考、选项、摘要、注释、变量更新、代码和已有图片语法被排除；正文仍完整可查。
3. 点「预览本帧正负词」，核对并编辑与 ComfyUI 实际发送一致的词；正向词上限 6000 字符，不自动截取。再点「仅生成关键帧 1 · ComfyUI」。每次点击只提交一次，不自动重试或回退云端。想保留同卡特征时，在配方区明确选锚定、填画风并点击「记住此角色卡配方」；仅本机生效，细节见[设计说明](<KEYFRAME-DESIGN.md>)。
4. 观察是否只新增一个 Comfy 任务、图库是否返回图片、聊天原文是否不变。若报错保留错误和任务号，先不要清日志或连点重试。

缺少唯一稳定来源身份、用户/系统消息、未验证的内嵌回合和 Sifang 路线会拒绝，不按可变楼层下标猜历史归属。

### 3. 历史重开（不再出图）

下载图片，关闭图库后从同一来源“查看 / 重开图片历史”；再刷新酒馆重开，确认图片仍在且不触发生成。切换其他楼层不应把该图归给新来源。图片保存原图、实际像素及有限参数；不会插入聊天或伪造图片标记。

来源绑定包含角色/群聊、聊天、稳定回复身份、swipe、完整原文SHA-256与本次任务。活动任务核对对象、变化事件、异步边界及保存前同步最后一跳；失效后须重新选择。无效Unicode源拒绝，正常中文/emoji不受影响。

## 取消、未知任务与历史保存

- “取消本地等待”不发送全局 interrupt。未提交的本地排队可取消；已提交服务端任务可能继续，请在 Comfy 自行核对，不能把关窗当GPU已停。
- 最小任务日志使用 sessionStorage，无正文/工作流/图片/凭据；不可用时退回内存并显示 page-only，不承诺跨窗口/跨会话恢复。
- 网络断开或提交未知时保留编号并阻止同URL新提交；满20条未确认记录拒绝新提交而不驱逐旧记录。恢复只GET原编号，不重发工作流；清本地日志也不取消服务端任务。
- 无原候选上下文的恢复图片只预览/下载，不编造历史归属。
- 聊天与图片存储不是同一事务。保存开始后换源/取消，提交可能仍完成，但只归不可变旧来源键，不能附到新聊天；保存期间继续busy，不声称原子回滚。
- Comfy单活跃组复用共享队列，不强降其他提供方并发；整体等待上限包含本地排队，另有单请求超时。

## 回滚

先停用实验扩展、核对是否还有未结束的Comfy任务。保留安装前配置/数据备份，不清空全部宿主存储或删除旧图。不要手工复制新旧JS混装。

版本回退仍走 Git：有原稳定来源时，使用宿主支持的Git安装/更新流程恢复已记录的仓库和稳定分支/标签；需要撤回此PR时，先由用户审核回退PR并合并，再通过宿主更新。不要假定宿主存在任意commit切换按钮，也不由代理自动回退或合并。新版配置不保证旧版都能识别，配置/图片恢复使用安装前备份与宿主支持方式；模型副本不必为回退而删除。
